## 2. 架构

结论：操作者的主机同时是控制面和数据落点；范围过滤是报告标注，不是网络隔离边界；出站分成「用户指定的平台与 Webhook」和「代码写死的公开情报源」两类。

- 组件：`main` / `run_pipeline`（`cybercensus.py` 7461–7653、7901–8038 行）串起锚点、被动源、平台、外部引擎、可选主动扫描、分级、`apply_scope`、基线与报告。GUI 用 `build_args`（`asm_gui.pyw` 158–233 行）构造同一套参数并在线程里调用流水线。`providers.py` 只负责查询和归一化。`tool_updater.py` 独立下载并替换 `tools/`。`run_scheduler`（7760 行起）按任务文件再拉起本程序。
- 信任边界：
  - 主机信任本目录下的 Python、bat，以及 `tools/`、`bin/`、程序目录和 PATH 中的引擎（`ext_path`，6816–6835 行）。
  - 平台密钥留在本机 `config.json` 或环境变量，请求发往各平台官方 API。
  - 目标名称、域名、IP 会发给 crt.sh、搜索引擎、RIPEstat、OTX、urlscan、Wayback、ip-api、whois 等。清单见第 3.2 节。
  - Webhook URL 由用户提供（7390–7391、6993–7016 行），内容是计数摘要，不是完整报告。
  - 更新器信任 GitHub Release，失败时再信任两个第三方代理（CC-01）。
- 数据与权限：输入经 `classify_target` / `-n -d --ip` 进入引擎；资产字典在内存中合并；报告写到 `--out`（默认 `cybercensus_out`）；基线为该目录下 `baseline.json`；别名缓存为程序目录 `aliases.json`（`.gitignore` 已排除）。没有守护进程端口、没有认证模块、没有容器挂载。主动扫描的交互确认在 CLI 的 `--yes` 与 GUI 的授权勾选；定时任务对部分参数自动加 `--yes`（CC-07）。
- 未读子系统：发布包里的 `CyberCensus.exe` 与 `tools/*.exe` 不在本树。无容器层可分析。

## 3. 代码安全

### 3.1 工具设计上的扫描能力

结论：端口扫描、C 段、ASN 扫描和 nuclei 需要显式开关；命令行默认仍会探测用户给出的域名，并在本机有 httpx/wafw00f 时连接目标。界面默认比命令行更进一步，会做敏感路径请求（CC-02）。

- 命令行默认不开 `--active`。`--cscan` 与 `--scan-asn` 会把 `active` 设为真（7364–7368、7915–7916、8001–8002 行）。未加 `--yes` 时要求输入 `yes`（7989–8000 行）。
- `--no-probe` 时跳过锚点 HTTP、httpx、wafw00f、nuclei（7551、5566–5572 行）。不加该旗标时，`build_anchors` 会对输入域名做 DNS 与 HTTP/TLS（4024–4067 行），`harvest_paths` 会取 robots.txt 与 sitemap（5768 行起，且 `no_probe` 为假时执行，7614–7616 行）。
- DNS 小字典默认开启，`--no-brute` 关闭（7401–7402、4180–4181 行）。只做解析。
- 外部引擎默认调用已安装的全部工具；nuclei 还要 `--active` 且非 `--no-probe`（5657–5660 行）。httpx 最多 300 个主机（6877–6891 行）。
- 敏感路径 18 条加域名备份名（3351–3389 行）。命令行仅 `--sensitive` 或 `--active` 时运行（7605–7611 行）。界面默认开关为开，见 CC-02。
- `--active` 对已收集 IP 做 TCP 连接，默认端口表含 22/445/3389/3306/6379/2375/9200 等（133–138、4421–4517 行）。非 Web 端口会发 Redis PING、Memcached stats、MongoDB isMaster 或读 banner（3220–3257 行）。这是工具能力，默认关闭。
- nuclei 调用本机二进制，严重级别参数为 `critical,high,medium`，最多 15 个 URL（6943–6955 行）。模板来自同目录 `nuclei-templates` 或 nuclei 自己的默认目录。
- 范围参数的实现是事后标注，见 CC-03。帮助文本写明 `--only-scope` 保留「范围内/相似」（7360–7361 行）。

### 3.2 对使用者与宿主机的真实风险

结论：对主机而言，最高风险是更新器在缺少校验和的情况下执行下载的二进制（CC-01），以及双击启动时的无哈希 pip（CC-08）。对授权而言，最高风险是界面默认模式会请求敏感路径（CC-02），且范围过滤挡不住已经发出的请求（CC-03）。已读源码中没有指向维护者自有域名的遥测。

- 高：CC-01 下载、镜像、执行 `-version`、再执行 nuclei 模板更新。CC-02 界面默认敏感路径。
- 中：CC-03 范围过滤滞后且 CIDR 被截成单 IP。CC-04 全局关闭 TLS 校验，Webhook 与情报源共用。CC-05 三个平台把密钥放在查询串，`config.json` 明文。CC-06 发布流水线跟踪 latest。CC-07 定时任务的授权名单偏窄，且会自动加 `--yes`。CC-08 bat 首次运行 `pip install`。
- 低：CC-09 明文 HTTP 把目标 IP/域名发给 ip-api 与 Wayback；whois/43。CC-10 Windows 上会执行 `tools/` 中的 `.bat/.cmd/.ps1`。
- 出站（功能目的，已在源码中写明 URL）：平台 API（`providers.py` 的 ENDPOINT）、crt.sh、Bing/360/百度/搜狗/DuckDuckGo/Mojeek、Wikidata、Wayback、OTX、urlscan、CertSpotter、Shodan InternetDB、RapidDNS、HackerTarget、ip-api、bgpview、RIPEstat、rdap.org、iTunes Search、whois.iana.org、GitHub/PyPI（仅更新器）。Webhook 仅在用户传入 URL 时发送一句计数（7636–7646 行）。
- 未发现 `shell=True`、`eval`、`exec`、`pickle`。`subprocess` 使用参数数组（`_run_ext` 6850–6857 行，调度器 7862–7869 行，nslookup 1738 行）。
- 报告 HTML 抽查到的标题、主机、证据使用 `html.escape`（6507 行附近）。未逐个插值证明，不把「无 XSS」写成已确认。PDF 通过本机 Edge/Chrome 无头打开本地 HTML（7176–7198 行）。
- 更新器解压时写入固定文件名（`_extract_exe` 187–199 行），读到的路径没有按 zip 成员路径写盘。
